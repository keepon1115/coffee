# 探究コーヒー

自宅でハンドドリップを楽しむ一人のための、スマホ用コーヒーノート。一杯を記録し、豆の背景（産地・品種・精製・工程）を読み、まだ記録にない産地や品種へ広げます。
データは端末のブラウザ内（IndexedDB）にだけ保存され、サーバー・アカウント・同期はありません。

設計の根拠は `統合設計・実装計画.md`、依頼は `実装モデルへの指示書.md` を参照。

## 構成

```
app/                 ← これがそのまま配布物（静的ファイルだけ）
  index.html, manifest.webmanifest, sw.js, css/, icons/
  js/
    app.js           起動・ルーター・外枠（3タブ）
    model.js         Bean/Tasting、日付（日・月・不明）、14列の対応表
    db.js            IndexedDB / メモリの保存層、Repo（一括保存・全置換）
    importer.js      XLSX取り込みの計画（追加/更新/スキップ）と反映
    xlsx.js          依存なしのXLSX読み取り
    backup.js        JSON完全バックアップ・検証・復元、Excel向けCSV
    knowledge-data.js  事典データ（PDFを再構成。個人の記録なし）
    knowledge.js     表記ゆれの正規化（国・品種・精製）と索引
    related.js       関連候補・比較の根拠（説明できるルールのみ）
    screens/         ノート / 事典 / 比較・気になる・設定・取り込み
tests/               node:test（保存・移行・バックアップ・関連・SW）
tools/               serve.mjs（確認用サーバー）, build-sw.mjs, make-icons.mjs, make-xlsx.mjs
samples/             架空データのサンプルxlsx（実データとは無関係）
```

## 起動・確認（PC）

```
node tools/serve.mjs        # http://localhost:8080/ （127.0.0.1のみ）
npm test                    # 32テスト
```
Node 20 以上。ビルド工程はありません。

**ファイルを変更したら配布前に必ず** `node tools/build-sw.mjs` を実行します（オフライン用キャッシュの一覧とバージョンを更新。忘れると `npm test` が失敗します）。

## スマホで使う手順

スマホでホーム画面追加とオフライン利用を行うには **HTTPS で開ける場所** に `app/` を置く必要があります（`http://パソコンのIP` ではPWA機能が働きません）。公開先の選定・アップロードは、この納品では行っていません。静的ファイルを置ける所ならどこでも動きます。

1. 配布先を決める（例: GitHub Pages / Cloudflare Pages / Netlify のドラッグ＆ドロップ。`app/` フォルダの中身をそのまま公開）。記録は端末内にしか保存されないので、URLが知られても個人の記録は見えません。ただし、URLを知る誰でもアプリ自体は開けます。
2. スマホのブラウザでそのURLを開く（初回のみ通信が必要。全ファイルが端末に保存されます）。
3. ホーム画面に追加 — iPhone(Safari): 共有 →「ホーム画面に追加」／ Android(Chrome): メニュー →「アプリをインストール」。
4. 右上の歯車 →「Excelから取り込む」で `コーヒー探究.xlsx` を選ぶ（スマホのファイルアプリ/ドライブ上に置いておく）。プレビューで件数を確認して取り込みます。
5. 以後は通信なしでも記録・検索・事典が使えます。

アプリを更新したときは、新しいファイルを置き換えて再度開くと次回起動で切り替わります。**記録はURL（オリジン）ごとに別です。** 配布先のURLを変えると記録は引き継がれないので、変更前にJSONで書き出してください。

## バックアップ（重要）

端末のブラウザデータ消去・機種変更・長期間の未使用で記録が失われることがあります。

- **完全バックアップ（JSON）**: 歯車 → 設定とデータ →「完全バックアップを書き出す」。豆・全感想・気になる・比較・取り込み履歴を含みます。スマホでは共有シートから「ファイルに保存」やドライブへ。月に一度程度を目安に。
- **復元**: 同じ画面の「JSONバックアップから復元」。件数を確認してから、いまの記録をバックアップの内容に置き換えます。不正なファイルや途中の失敗では、いまの記録は変わりません。
- **Excel向けCSV**: 1感想1行（感想のない豆も1行）、UTF-8 BOM付き。Excelで読む・手元に残す用で、**CSVからの復元はできません**（完全な復元はJSON）。年月だけの日付（例 `25/9`）はExcelが日付に自動変換して表示することがあります。元の表記は「元の日付表記」列と、JSON側に残ります。
- 元の `コーヒー探究.xlsx` は読み取るだけで変更しません。取り込み後もそのまま保管してください。

## 14列の行き先（Phase 0 の対応表）

| Excel列 | 保存先 |
|---|---|
| 日付 | Bean.recordDate と、感想があれば Tasting.date（精度: 日／月／不明。元の表記を `raw` に保持。`26/10` → 2026年10月・月精度。空欄は不明のまま） |
| 店名/購入場所 | Bean.store |
| 原産国 | Bean.country（原文）＋ norm.countryId（KENYA/Kenya/ケニア を同じ産地に） |
| 名称 | Bean.name |
| 生産地・生産者・精製所/農園・標高 | Bean.region / producer / farm / altitude |
| 精製方法 | Bean.process（原文）＋ norm.processIds（複数可） |
| 品種 | Bean.variety（原文）＋ norm.varietyIds（複数可） |
| フレーバーノート | Bean.shopNote（「お店のフレーバーノート」として別枠表示） |
| 感想 | Tasting.text（原文のまま。空欄の行から空の感想は作らない。「2回目」とあっても分割しない） |
| URL / AIメモ | Bean.url / Bean.aiMemo |

豆と感想は別レコードで、同名の豆は自動統合しません。感想の追記は常に新しいレコードで、既存の感想は上書きされません。再取り込みは行内容のハッシュで検出し、同じ内容はスキップ、Excelで変わった行は「更新」候補（既定ではオフ）として確認します。

### 未確認・限界（正直に）

- **スマホ実機は未確認**。iPhone/Androidでのホーム画面追加、オフライン起動、ファイル選択（xlsx/JSON）、共有シートでの保存、キーボード表示中の保存ボタンの位置は、この環境では試せていません。最初に実機で通しの確認をしてください。
- **画面の見た目の目視確認は未実施**（この環境ではスクリーンショットが取得できなかったため、DOMとレイアウト数値で確認）。配色・余白・行間は実機で見て調整してください（CSSの変数は `app/css/app.css` 冒頭）。
- **公開（HTTPS配布）は未実施**。ユーザーと公開先を決めてからです。
- **事典の内容は元のPDFの記述を再構成したもの**で、各主張を一次資料で再確認してはいません（出典と「確認時点 2026-10-24（PDFによる）」を各ページに表示）。店の公式リンクも未再確認です。
- 産地ページの「歴史・文化」のうち、PDFに無い部分は私の一般的な知識による短い補足で、**「編集メモ・要確認」** と明示しています（タイ、インドネシア、インド、エチオピア、ケニア、ルワンダ、コロンビア、ブラジル、コスタリカ、イエメン）。PDFに記述がない国は「未収録」と表示し、推測で埋めていません。東ティモール・ベトナムは事典に表が無いため、解説ページは空の「未収録」です（記録の原文は残ります）。
- PDF内の個人向け提案（好みの仮説・購入計画・店の優先順位）、相場・競売価格など時事性の高い数値、記録項目の追加案は、要件として実行せず収録していません。
- 品種の紐づけは語句の照合です。未知の品種名（Welisho、Ruiru 11、IH-90 など）は事典につながず、原文のみ残ります。「ピンクブルボン」は流通名の注意を付けて別ページにしています。
- 焙煎度は任意の補助項目として入力欄だけ追加しました（Excelに列がないため、取り込み直後は空欄）。
- ブラウザの「サイトデータ削除」で記録は消えます。保存領域の永続化は最初の保存後に依頼しますが、許可はブラウザ次第です。
